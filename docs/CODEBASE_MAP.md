## System Overview

**DnDTools** is a **Streamlit web app** providing two D&D 5e tools in a single
tabbed page:

1. **Loot Creator** — generates balanced magic items via the Google Gemini API,
   with a quantitative power-scoring system that suggests an appropriate rarity.
2. **Encounter Tracker** — a combat/initiative tracker for running encounters.

The app is pure Python. Feature code lives in two feature packages
(`loot_creator/`, `encounter_tracker/`) plus a shared `utils/` package and a
flat `config.py`. Persistence is plain JSON files in `data/`.

## Module Guide

### Entry — `app.py`

**Purpose**: Configures the Streamlit page, renders the sidebar (API key input),
and wires the two feature tabs.
**Entry point**: `main()` (run via `streamlit run app.py`).
**Exports**: `render_sidebar()`, `main()`.
**Dependencies**: `streamlit`, `loot_creator.ui.render_loot_creator`,
`encounter_tracker.ui.render_encounter_tracker`.
**Notes**: Initializes `st.session_state["user_api_key"]` with a guard. The API
key is held in session state only — never persisted, lost on refresh.

### `config.py`

**Purpose**: Central constants — file paths, D&D 5e reference lists, the Gemini
model name; loads `.env` via `python-dotenv`.
**Key exports**: `GEMINI_API_KEY`, `GEMINI_MODEL`, `DATA_DIR`,
`SAVED_ITEMS_FILE`, `SAVED_ENCOUNTERS_FILE`, `SRD_MONSTERS_FILE`,
`D5E_CONDITIONS`, `DAMAGE_TYPES`, `ABILITY_SCORES`, `CLASSES`, `ALIGNMENTS`.
**Gotcha**: All paths are **relative** — the process must run from the repo root.

### `utils/` — shared storage

**Purpose**: Thin JSON I/O layer; the only shared utility.
**Exports**: `load_json(filepath, default)`, `save_json(filepath, data)`.
**Patterns**: Defensive read (returns `default` on missing/corrupt file);
auto-creates `data/` on every write. No file locking.

### Module — `loot_creator/`

**Purpose**: Generate balanced magic items via Gemini, scored for power level.
**Entry point**: `render_loot_creator()` (`ui.py`).

| File | Purpose | Tokens |
|------|---------|--------|
| ui.py | Streamlit UI: quick/advanced mode, power-score display, saved items | 3641 |
| balance.py | Power-score formula, `RARITY_POWER_RANGES`, rarity suggestion | 2483 |
| templates.py | Builds detailed/quick Gemini prompts from parameters | 1798 |
| models.py | Pydantic models + enums (`LootParameters`, `MagicItem`, ...) | 1656 |
| generator.py | Calls Gemini API, extracts/parses JSON into `MagicItem` | 1105 |
| __init__.py | Re-exports public API | 189 |

**Key flow**: `ui.py` builds a `LootParameters` (advanced) or
`QuickLootParameters` (quick) → `balance.calculate_power_score` shows a live
score → `generator.generate_item` builds a prompt via `templates` and calls
Gemini → response parsed into a `MagicItem` → saved to `data/saved_items.json`.

**Power-score formula** (`balance.py`):
`Score = [(ΔDPR × ActionEcon × Usage) + Defense + Control] × Reliability − Constraints`.
`get_suggested_rarity` maps the score to a `Rarity` via `RARITY_POWER_RANGES`
(Common 0–2, Uncommon 2–5, Rare 5–10, Very Rare 10–18, Legendary 18–30,
Artifact 30–100).

### Module — `encounter_tracker/`

**Purpose**: Track a live combat encounter (initiative, HP, conditions, rounds).
**Entry point**: `render_encounter_tracker()` (`ui.py`).

| File | Purpose | Tokens |
|------|---------|--------|
| ui.py | Streamlit UI: creature cards, add form, HP controls, save/load | 2465 |
| models.py | `Creature`, `Encounter` Pydantic models with turn/HP logic | 652 |
| combat.py | `roll_d20`, `roll_initiative`, `sort_by_initiative`, damage/heal | 448 |

**Key flow**: The live `Encounter` lives in `st.session_state.encounter`. The add
form pulls from `data/srd_monsters.json` or manual entry. Save/Load round-trip
through `data/saved_encounters.json` (upsert by name).

## Conventions

- **Feature packages** each have `models.py`, `ui.py`, and a logic module
  (`combat.py`; or `generator.py` + `balance.py` + `templates.py`).
- **Pydantic v2** for all models: `Field(...)` validation, `.model_dump()` to
  serialize, `Model(**dict)` to reconstruct.
- **Enums** all inherit `(str, Enum)` — values are human-readable strings reused
  directly as UI labels and in prompts.
- **Session state** initialized with `if "key" not in st.session_state` guards.
- **File I/O** always via `utils.load_json` / `utils.save_json` — never direct
  `open()` in feature code.
- **UI entry points** follow the `render_*` naming convention.
- **Widget keys**: creature-indexed (`creature_{index}_*`) or mode-prefixed
  (`quick_*`).

## Gotchas

- **Relative paths everywhere.** `config.py` paths and
  `utils.storage.ensure_data_dir()`'s hardcoded `"data"` require the app to run
  from the repo root.
- **API key is ephemeral** — stored only in `st.session_state["user_api_key"]`,
  with `config.GEMINI_API_KEY` (from `.env`) as fallback in `generator.py`.
- **Gemini model name** is a single constant `GEMINI_MODEL` in `config.py`. If
  generation fails with a model error, verify the name against the google-genai
  SDK's supported models.
- **No retry logic** in `generator.py`; transient API errors surface to the UI
  as `st.error`.
- **Dead/incomplete code**: `combat.apply_damage`/`apply_healing` are unused (UI
  mutates HP inline); `get_hp_color` and card `border_color`/`bg_color` are
  computed but never applied to widgets.
- **Save is append-only** for items (no dedup); encounters upsert by name.
- **`sort_by_initiative` is non-idempotent** — a `random.random()` tiebreak
  reorders ties on each call.
- **UI/model gaps**: `PassiveBonuses.saving_throw_bonuses` and
  `AdditionalProperties.immunities` exist in the model but have no Advanced-mode
  widget.

## Navigation Guide

**To add a new SRD monster**: edit [data/srd_monsters.json](data/srd_monsters.json)
(`{name, hp, ac, initiative_modifier, cr}`); no code change needed.

**To change the AI prompt**: edit [loot_creator/templates.py](loot_creator/templates.py)
(`build_item_prompt` list-builder; `build_quick_item_prompt` f-string).

**To change balancing rules**: edit the constants and formula in
[loot_creator/balance.py](loot_creator/balance.py) (`USAGE_MULTIPLIERS`,
`RARITY_POWER_RANGES`, value/penalty constants).

**To add a new item type/subtype**: add enum values in
[loot_creator/models.py](loot_creator/models.py) and extend `SUBTYPE_MAP` in
[loot_creator/ui.py](loot_creator/ui.py).

**To change the Gemini model**: edit `GEMINI_MODEL` in
[config.py](config.py).

**To add/modify the API key flow**: `render_sidebar()` in
[app.py](app.py) (capture) and `_get_api_key()` in
[loot_creator/generator.py](loot_creator/generator.py) (consume).

**To add a D&D condition / damage type**: edit the lists in
[config.py](config.py) (`D5E_CONDITIONS`, `DAMAGE_TYPES`).

**To add a UI section**: add a `render_*` function in the relevant feature's
`ui.py` and call it from `render_loot_creator()` / `render_encounter_tracker()`.
